# lib-svg

SVG 1.1 / SVG 2 parsing, styling, layout and rendering for Silk. This repository
was extracted from `silk-lang/nonstd` revision
`7d6c3693a9ad1fec24127985626ab4224f9f1995`; it retains the complete SVG sources,
unit tests, reviewed reference corpus, fonts, specifications and benchmark history.
[Rendering coverage](modules/README.md), [specification decisions](modules/SPECIFICATIONS.md)
and [remaining limitations](modules/LIMITATIONS.md) distinguish implemented behavior
from known failures. Extraction does not promote known failures to passes.

## Packages and support boundary

Public libraries live under `modules/` and retain their package names:

| Path | Package |
| --- | --- |
| `modules` | `svg` |
| `modules/render` | `svg-render` |
| `modules/raster` | `svg-raster` |
| `modules/filters` | `svg-filters` |
| `modules/text` | `svg-text` |
| `modules/gpu` | `svg-gpu` |

The root `svg-render-test-harness` executable is internal verification tooling,
not an installed product CLI or stable application interface. It retains native
file rendering, resource confinement, viewport, font, language, animation and
fragment options. `modules/tools/wasm` retains the wasm utility and JavaScript host.
`modules/tests`, `modules/gpu/tests`, `modules/bench`, `xml-compatibility` and `xml-conformance`
are internal tests, corpus and diagnostic programs, not public library APIs.
The root `lib-svg-tasks` package and the `bootstrap` package are likewise
repository-only automation; their native parser dependencies do not reach library consumers.

XML is the installed compiler's **`silk.xml`** (`XmlDocument`, `XmlNodeId`, etc.).
There is no local XML parser or compatibility facade. `xml-compatibility` carries
all original local XML tests against that API; `xml-conformance` drives the pinned
W3C XML suite with the original namespace-aware, nonvalidating selection policy.
The pseudo-attribute API accepts strings, so invalid UTF-8 is rejected at the
checked `String.fromUtf8` boundary before parsing.

CSS, fonts, graphics and native GPU support are exact-revision Git dependencies
on `https://github.com/silk-lang/lib-{css,fonts,graphics,native}.git`. Internal SVG
edges alone use local paths. The workspace does not contain another repository's
libraries. Keep direct and transitive revisions identical: Silk rejects duplicate
named packages from distinct checkouts. First fetches must be serial; do not run
concurrent first-use builds for the same revision. Dependency runtime payloads
are resolved from `$SILK_HOME/git/<revision>` (default `~/.silk/git/<revision>`),
never from neighboring development checkouts. Shader sources/generated inputs
belong to the pinned graphics/native packages and arrive through Silk fetching.

## Prerequisites

- Silk **0.1.0-dev.64+8214c402307b**, LLVM **22.1.8**, with `SILK_CLANG` an absolute
  path to its Clang executable. Tasks use the compiler selected by `silk task`.
- Node **22 or newer** for the JavaScript-facing WebAssembly runtime adapter.
  Corpus control, assertions, downloads and reports are Silk code.
- GNU coreutils (`timeout`; `gtimeout` on macOS) for bounded child processes, and
  `curl` for authenticated downloads. On Windows use GNU/MSYS2 `timeout`, not the
  unrelated Windows console command.
- Git, CMake and host C/C++ toolchains for pinned Lexbor 2.5.0 (HTML5 parsing)
  and Xerces-C 3.3.0 (namespace-aware XML 1.0/1.1 validation). These preserve WPT
  discovery without the standard XML DOM parser's fixed depth limit. Before
  the main task program, run:

  ```sh
  silk task --manifest-path bootstrap/silk.toml install-lexbor
  silk task --manifest-path bootstrap/silk.toml install-xerces
  ```

  They are installed under `.cache/lexbor` and `.cache/xerces`; Windows also
  needs `.cache/lexbor/bin` on `PATH` for its DLL. The Xerces validator links its
  parser statically and has network access disabled. Library builds do not
  depend on these tooling parsers; rendering and XML conformance still use
  the installed `silk.xml`.
- libarchive for streaming, bounded archive extraction (system library on macOS;
  `libarchive-dev` on Debian/Ubuntu). On Windows provide its compatible `archive`
  import library under `.cache/libarchive/lib` and its DLL on `PATH`.
- `wasm-ld` on `PATH` for wasm builds. Native builds require the host SDK/linker.
- The full parity/conformance protocol uses Linux, `fonts-dejavu-core` and
  `fonts-freefont-ttf`. Wasm/native parity fixes its initial font to
  `/usr/share/fonts/truetype/dejavu/DejaVuSerif.ttf`; WPT also requires
  `/usr/share/fonts/truetype/freefont/FreeSans.ttf`.
- GPU tests require a WebGPU-capable native backend (CI uses Mesa lavapipe) and
  the Dawn payload fetched/generated by the pinned native package. Windows
  provisioning invokes that package's `prepare-windows` Silk task.
- Reference benchmarks additionally require Cargo/Rust supporting edition 2024
  (the recorded baseline used Rust 1.96.0), `gzip`, and `cjpeg` from libjpeg-turbo
  for authored JPEG workloads. Callgrind is optional and Linux-only.

Lexbor and Xerces-C revisions are pinned in `bootstrap/src/tasks.silk`; LLVM,
Dawn and Mesa pins come from lib-native's `setup-ci` task. CI bootstraps the
exact Silk release with its official installer and Clang 22 before the first
task. Repository automation lives in `src/tasks.silk`; `silk task` lists the
commands.

`silk task setup-ci` provisions through the pinned lib-native package's Silk
tasks; add `--linux-gpu` for lavapipe. Fetch that dependency first with
`silk check --manifest-path modules/gpu/tests/silk.toml`. Windows GPU builds
invoke its `prepare-windows` task before compiling and staging runtime DLLs.

## Reproducible verification

Run from this repository root, after setting `SILK_CLANG` and installing Silk:

```sh
silk task check
silk task test-gpu
silk task check-wasm
silk task check-xmlconf --report build/svg/xmlconf.json
```

The main gate serially checks every workspace package, checks formatting, runs
all reachable Silk unit tests (including XML, harness options and tooling),
builds the release harness, renders every own/malformed fixture manifest and checks
the curated resvg corpus. These gates use committed fixture fonts rather than scanning
host font directories on each invocation. The gate also verifies the IDNA generator
and selected pinned specification bytes. `--offline` verifies populated caches;
`--skip-fetch` deliberately omits reference/IDNA fetching and the external corpus,
not local tests or own fixture rendering. Full GPU and wasm comparisons are
separate commands above. No tests of unrelated CSS/font/graphics packages are
silently copied into this repository's gate.

```sh
# Unit tests only; no rendering or reference downloads.
silk test --manifest-path xml-compatibility/silk.toml --root src/tests.silk
silk test --manifest-path silk.toml --root src/tests.silk
# All reviewed external SVG suites plus XML, with per-suite original viewports/fonts.
silk task conformance
# Explicitly regenerate the locked IDNA table, or verify it without source edits.
silk task generate-idna --fetch
silk task generate-idna --fetch --check
# Internal command-line rendering; choose your native target's build directory.
silk build --release --manifest-path svg-render-test-harness/silk.toml
build/llvm/x86_64-unknown-linux-gnu/release/svg-render-test-harness input.svg -o output.png
# Wasm utility; prints the module path.
silk task build-wasm
# Benchmark setup and measurement (not part of the rendering gate).
silk build --release --manifest-path modules/bench/silk.toml
silk task benchmarks rust-build
silk task benchmarks bench --silk build/llvm/x86_64-unknown-linux-gnu/release/svg-bench --fetch-workloads --record-baseline --baseline build/svg/current-baseline.json --output build/svg/bench.json
silk task benchmarks ab /path/to/old/svg-bench /path/to/new/svg-bench --output build/svg/ab.json
```

[Testing](modules/docs/testing.md) documents individual fetch/reftest commands and
expectation semantics. [Performance](modules/docs/performance.md) preserves historical
measurements and specialized compressed/image/sampling/nested/orientation workflows.
Reports and downloaded corpora are ignored build/cache artifacts. Full conformance
and benchmarks run on a schedule or explicit CI dispatch; known pixel differences
remain explicit reviewed failures, and unexpected passes fail the gate too.

## Assets and licenses

Committed fixture SVGs, raster payloads and `modules/tests/fonts` are included; normal
builds never regenerate them or depend on UI/example assets. The font directory
retains each upstream license and provenance. Library licensing remains MIT or
Apache-2.0; upstream notices are retained in `LICENSE-MIT` and `LICENSE-APACHE`.
Unicode data embeds its Unicode-3.0 notice. Fetched specifications/test suites keep
their upstream licenses. Tiger is an explicitly fetched AGPL-3.0-or-later benchmark
input, not a distributed runtime dependency.

Fixture-authoring tasks are explicit: `silk task fixtures all` or select an
individual generator, for example `silk task fixtures mesh`. Builds and checks
consume committed outputs without regenerating them. Fixture image/font writers
are Silk code; Python, Pillow and fontTools are not required.
